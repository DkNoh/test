# BASE 권한 모델

> 다른 내부 업무시스템으로 재사용하기 위한 기본 권한 체계입니다.

## 기본 역할

| 역할 | 용도 |
|---|---|
| `ROLE_ADMIN` | 시스템 관리자. 메뉴/권한/공통코드/사용자 관리 가능 |
| `ROLE_MANAGER` | 업무 관리자. 담당 업무의 조회, 저장, 승인 가능 |
| `ROLE_USER` | 일반 사용자. 담당 업무의 조회와 제한적 저장 가능 |
| `ROLE_VIEWER` | 조회 전용 사용자. 목록/상세/엑셀 권한만 부여 |

## 권한 단위

| 권한 | 의미 |
|---|---|
| `READ` | 화면 접근, 목록/상세 조회 |
| `WRITE` | 등록, 수정, 삭제 |
| `APPROVE` | 승인, 반려, 상태 변경 |
| `EXCEL` | 엑셀 다운로드/업로드 |
| `ADMIN` | 메뉴, 권한, 시스템 설정 관리 |

## `TB_MENU_AUTH` 표준 컬럼

| 컬럼 | 의미 | 기본값 |
|---|---|---|
| `MENU_CD` | 메뉴 코드 | 필수 |
| `AUTH_CD` | 역할 코드 | 필수 |
| `CAN_READ` | 화면 접근, 목록/상세 조회 | `Y` |
| `CAN_WRITE` | 등록, 수정, 삭제, 제출 | `N` |
| `CAN_APPROVE` | 승인, 반려, 결재 처리 | `N` |
| `CAN_EXCEL` | 엑셀 다운로드/업로드, 파일성 내보내기 | `N` |

## 메뉴 권한 원칙

- 좌측 메뉴 노출은 `TB_MENU`와 `TB_MENU_AUTH` 기준으로 처리한다.
- 메뉴 숨김은 사용자 편의 기능일 뿐이며, 실제 URL 접근은 서버에서 다시 검증한다.
- `/data`, `/save`, `/delete`, `/excel` 같은 하위 API는 부모 화면 URL과 명시적으로 연결해 권한을 판단한다.
- `Referer` 헤더만으로 권한을 허용하지 않는 구조를 최종 목표로 한다.

## 서버 권한 매핑 기준

| URL suffix | 필요 권한 |
|---|---|
| 화면 URL, `/data`, `/search`, `/tree-data`, `/auth-data` | `READ` |
| `/save`, `/create`, `/update`, `/delete`, `/submit` | `WRITE` |
| `/approve`, `/reject`, `/process` | `APPROVE` |
| `/excel`, `/upload`, `/download` | `EXCEL` |

좌측 메뉴는 `CAN_READ = 'Y'`인 메뉴만 노출한다. 버튼 표시와 API 호출은 각 액션 권한을 기준으로 분리한다.

## 프로젝트 적용 규칙

- 새 프로젝트에서 역할명이 달라지면 이 문서를 먼저 수정하고 seed 데이터와 화면 콤보 값을 맞춘다.
- 권한 코드가 늘어나면 `MenuAuthInterceptor`, 메뉴 관리 화면, seed SQL, 문서가 함께 갱신되어야 한다.
- 개인정보 조회, 엑셀 다운로드, 권한 변경은 감사 로그 대상이다.
