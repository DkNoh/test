# HANDOFF.md 효율적 활용 가이드

## ① INTENT
`HANDOFF.md` 파일의 단순 세션 전환(토큰 만료) 용도를 넘어, 컨텍스트 동기화, 체크포인트, 작업 지시서 용도로 활용하는 효율적인 방안을 설명합니다.

## ② RISK & BLAST RADIUS
- **리스크**: `HANDOFF.md`가 최신 상태로 갱신되지 않으면, AI가 과거의 상태(이미 해결된 버그, 폐기된 아키텍처 결정)를 바탕으로 잘못된 코드를 생성할 위험이 있습니다.
- **방어 전략**: 세션 종료 전이나 주요 작업(PR 생성 등) 완료 시점에 AI에게 지시하여 `HANDOFF.md`를 스스로 업데이트하도록 강제합니다.

## ③ MIGRATION PATH (효율적인 사용법)

1. **작업 지시서 (Task Backlog) 및 진척도 관리**
   개발자가 직접 코딩하기 번거로운 작업 목록이나 발견된 버그를 `HANDOFF.md`의 체크리스트(`- [ ]`)에 누적해 둡니다. 세션 시작 시 "HANDOFF.md 읽고 미해결된 최우선 항목부터 진행해"라고 지시하면 즉각적인 작업 착수가 가능합니다.

2. **동적 컨텍스트 및 단기적 아키텍처 결정 전파**
   `CLAUDE.md`가 변하지 않는 헌법(글로벌 규칙)이라면, `HANDOFF.md`는 일일 업무 일지입니다. "최근 `dto`에서 `vo`로 패키지 변경 합의 완료"와 같은 단기적 결정 사항을 명시하여, AI가 레거시 코드를 참고하다가 실수로 예전 패턴을 모방하는 것을 차단합니다.

3. **디버깅 이력 보존 (오답 노트 공유)**
   동일한 에러로 3회 이상 실패하거나 세션이 만료될 경우, 시도했던 방법들과 실패 원인, 에러 로그를 `HANDOFF.md`에 기록합니다. 새로운 AI 세션이 동일한 헛수고(API 우회, 꼼수 등 금지된 패턴 시도)를 반복하지 않고 다음 단계의 원인 분석부터 시작할 수 있습니다.

4. **작업 체크포인트 (상태 스냅샷)**
   퇴근 전이나 큰 단위의 리팩토링 중단 시, 현재 어디까지 코드를 수정했고 다음 세션에서 어떤 파일을 수정해야 하는지 구체적인 위치(파일명, 패키지)를 기록하여 흐름 단절을 막습니다.

## ④ CODE

```markdown
// BEFORE (단순 인계 용도)
- 현재 세션 토큰 만료됨.
- 다음 AI는 스캐폴드 컨트롤러 수정 작업을 이어서 할 것.

// AFTER (효율적인 상태 저장 및 지시 용도)
## 🎯 현재 작업 목표 (진행 중)
- [ ] `AccountController` 내 사용자 목록 조회 시 권한 필터링 버그 수정
  - 참고: 특정 상황에서 ADMIN 권한이 없는데도 삭제 버튼이 노출되는 이슈가 있음.

## 📝 최근 합의된 기술 결정 사항
- (2026-06-04) VO 생성 패키지를 `dto.<module>`에서 `vo.<module>`로 일괄 변경. 새로 생성하는 모든 파일은 이 규칙을 따를 것.

## 🐛 디버깅 히스토리 (오답 노트)
- 로그인 403 에러 발생 중.
- 시도 1: `GlobalExceptionHandler`에 catch 추가 (효과 없음, 에러 도달 안 함)
- 추정 원인: Spring Security FilterChain 단에서 인증 객체가 누락된 것으로 보임. 다음 세션에서는 Filter config부터 확인할 것.
```
