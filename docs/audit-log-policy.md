# 감사 로그 정책

> `@PrivacyLog`를 붙이면 AOP가 자동으로 감사 로그를 기록한다. 이 문서는 어떤 기능에 반드시 `@PrivacyLog`를 붙여야 하는지 정하는 BASE 기준이다.

## 기본 원칙

- 개인정보, 민감정보, 권한, 대량 데이터에 접근하는 기능은 감사 로그 대상이다.
- 화면 버튼을 숨기는 것과 별개로 서버 메서드 기준으로 기록한다.
- 조회성 기능도 개인정보가 포함되면 기록한다.
- 엑셀/파일 다운로드는 목록 조회보다 더 강한 감사 대상이다.
- 실패한 요청도 가능한 범위에서 원인 추적이 가능해야 한다.

## 필수 적용 대상

| 구분 | 대상 | 예시 |
|---|---|---|
| 개인정보 목록 조회 | 이름, 전화번호, 주민번호, 고객번호, 계좌 관련 정보가 포함된 목록 | SMS 이력, 고객별 조회, 주민번호 조회 |
| 개인정보 상세 조회 | 목록 행 클릭 후 상세 팝업/상세 화면 | 발송 상세, 고객 상세, 사용자 상세 |
| 대량 반출 | 엑셀 다운로드, CSV 다운로드, 파일 다운로드 | `/excel`, `/download` |
| 파일 처리 | 개인정보 포함 파일 업로드/다운로드 | 수신자 업로드, 발송 대상 파일 |
| 권한 변경 | 사용자 역할, 메뉴 권한, 접근 권한 변경 | 메뉴/권한 관리, 사용자 권한 변경 |
| 사용자 정보 변경 | 사용자 등록/수정/삭제, 부서 변경 | 사용자 관리, 부서/사원 관리 |
| 승인/반려 | 결재, 승인, 반려, 상태 변경 | 캠페인 승인, 발송 대상 승인 |
| 발송/예약 | SMS/LMS/알림톡 발송 요청, 예약, 취소 | 발송 등록, 재발송, 발송 취소 |
| 보안 이벤트 | 로그인 성공/실패, 잠금, 비밀번호 변경 | LDAP 로그인, 계정 잠금 |

## Controller 적용 기준

아래 유형의 Controller 메서드에는 `@PrivacyLog` 적용을 우선 검토한다.

```java
@PrivacyLog(action = "SMS 이력 목록 조회")
@GetMapping("/data")
public ResponseEntity<?> getData(...) { ... }

@PrivacyLog(action = "SMS 이력 엑셀 다운로드")
@GetMapping("/excel")
public void downloadExcel(...) { ... }

@PrivacyLog(action = "메뉴 권한 변경")
@PostMapping("/save")
public ResponseEntity<?> save(...) { ... }
```

## 액션명 작성 규칙

- 사용자가 이해할 수 있는 업무명으로 작성한다.
- 메뉴명 + 행위 형태를 권장한다.
- 예:
  - `SMS 이력 목록 조회`
  - `고객별 SMS 조회`
  - `주민번호 조회`
  - `SMS 이력 엑셀 다운로드`
  - `메뉴 권한 변경`
  - `사용자 정보 수정`
  - `캠페인 승인 처리`

## 마스킹 기준

- 화면 표시 데이터는 `MaskingUtil`로 마스킹한다.
- 감사 로그에는 원문 전체를 남기지 않는다.
- 대상 식별이 필요하면 PK, 업무번호, 마스킹된 전화번호, 마스킹된 이름처럼 최소 정보만 남긴다.
- 주민번호, 전문 메시지 본문, 대량 수신자 목록 원문은 로그에 직접 저장하지 않는다.

## 스캐폴드 생성 시 기준

- 개인정보 포함 화면은 생성 후 `getData`, `detail`, `excel` 계열 메서드에 `@PrivacyLog`를 붙인다.
- 스캐폴드가 자동으로 `@PrivacyLog`를 생성하도록 개선할 수 있지만, 기본값으로 모든 화면에 무조건 붙이지 않는다.
- 생성 시 다음 선택값을 받는 방식이 적절하다.

```text
개인정보 포함 여부: Y/N
엑셀 다운로드 포함 여부: Y/N
권한/승인 기능 포함 여부: Y/N
```

선택값이 `Y`인 경우에만 관련 메서드에 감사 로그 annotation을 생성한다.

## 폐쇄망 반입 시 주의

- 스캐폴드 생성기는 `@Profile("local")` 전용으로 유지한다.
- 개발서버(dev)와 운영서버(prod) 프로파일에서는 스캐폴드 URL이 노출되지 않아야 한다.
- 금융 폐쇄망에 반입할 때는 스캐폴드 사용 가능 범위를 사전에 승인받는다.
- 자동 생성 코드는 반드시 사람이 검토하고, 실제 DB 컬럼/권한/감사 로그 기준을 확인한 뒤 반영한다.
- 스캐폴드 생성기 자체를 운영 산출물에 포함할지, 개발용 도구로만 둘지는 프로젝트 보안 기준에 따라 결정한다.
